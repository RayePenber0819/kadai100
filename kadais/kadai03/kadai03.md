## 【課題03】Webの基礎2.Webサーバを立ち上げてWebの仕組みを知る（動的ページ編）

[問題]
```
アクセスするたびに表示する内容が変わります。
つまり予めHTMLを用意しておくことはできません。
http://localhost:8000/time で以下のような画面が表示されるようにしてください。
「サーバ側でHTMLを組み立てて最終的にできたものをクライアントに返す」のイメージをつけてください。
Chromeで右クリックメニューから「ソースの表示」を見るとサーバから返ってきたHTMLが確認できます。「サーバ側でHTMLを組み立てて最終的にできたものをクライアントに返す」のイメージをつかんでください。
```

[ヒント]
```
server.mount_proc というものを使います。それが何者かまでは深く知る必要はありません。この例で言うと「/timeというURLに対してリクエストがきたら<html><body></body></html>
という文字列をリクエストボディに詰めてクライアントに返してあげるという処理です。
これを参考に今回の課題を解いてみてください。
```

```
server.mount_proc("/time") do |req, res|
  # レスポンス内容を出力
  body = "<html><body></body></html>"
  res.status = 200
  res['Content-Type'] = 'text/html'
  res.body = body
end
```

また、現在時刻はTime.new でも Time.now でもなんでもOKです。

注意: webrick.rbを修正したらサーバを再起動しないと反映されません！！！

## 理解してほしいこと

```
サーバの役割とは何かをクライアントに返すこと
↓
レスポンスは単なる文字列である
↓
原則、ブラウザはHTML形式の文字列を解釈する。なのでHTML形式にのっとった文字列を作って返してやる必要がある。「<html><body><head>~~~」← これは単なる<、h、m、lという文字の繋がりに過ぎない。
↓
rubyなどのプログラミング言語を使ってガリガリHTMLを構築していく。PHPだろうがPythonだろうが結局は最終的にはそこに帰結する。「動的なページ」とはそういうこと。

（この課題のゴールはここまで）
↓
ただ body ="<html><body>#{DateTime.now}</body></html>" とかを書くのは面倒だし可読性も悪い。Railsでいうとコントローラにこれを書いてるイメージ。
↓
見た目にかかわるものはそれ専門部隊にお願いした方がよさげ。
↓
MVCのViewの登場（erbとかslimとか）

こういった背景を理解が重要。
```
